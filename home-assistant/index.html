Smart-Home-Edge-Systems.us / Home Assistant architecture

Make the home understand itself.

Home Assistant is the automation and experience layer of the Barnes Home Lab: a local system for connecting devices, presenting useful state, coordinating services, and turning infrastructure into something a household can actually use.

The architecture is designed to be demonstrated, documented, and communicated clearly: a practical foundation for private smart-home control that can grow into a trustworthy, marketable local-first solution.

01 / System architecture

A local control plane for the home.

Home Assistant sits inside a wider Proxmox design where compute, voice, storage, networking, and recovery services have clear responsibilities.

VM 101 / Home Assistant OS

The automation host

The documented HAOS node uses 2 vCPUs, 4 GB RAM, and 32-64 GB NVMe storage. It has a primary LAN address of 192.168.86.251 and an isolated backend address of 10.0.10.1.

  • NFS backup mount: /mnt/haos_backups
  • Backup source: Samba-NAS shares/backups/haos
  • Role: integrations, dashboards, devices, and automation
Compute services / local dependencies

Supporting the experience

The compute node provides the services Home Assistant can coordinate or depend on while keeping the system locally operated.

  • Pi-hole and Unbound for DNS
  • Nginx Proxy Manager for service routing
  • Ollama for local AI workloads
  • Wyoming Piper, Whisper, and Open WebUI
  • Twingate Connector for secure remote access
Storage and recovery / shared foundation

Keep the system recoverable

The storage architecture provides the central file layer and preserves HAOS backups alongside configuration exports, database dumps, and service records.

  • SMB/NFS gateway at LXC 100
  • HAOS backup share under homelab-backups
  • Cold-sync status retained with recovery records
Architecture areas / planned documentation

Services to document

The file structure reserves guides for the Home Assistant system, integrations, front end, media, network, Proxmox, security, climate, utilities, alerts, and resilience.

  • Matter Server and Mosquitto Broker
  • Duck DNS, ESPHome Builder, and go2rtc
  • Node-RED and rtlamr2mqtt
Voice and edge devices: the Satellite and ESPHome designs are discussed in smart-home-edge-systems/voice/index.html. That page will be updated later with the dedicated voice and edge-device documentation.
