Smart Home Edge Systems / Working lab

Research that becomes useful at home.

The R&D hub is where prototypes become dependable deployments. We test local AI, voice pipelines, private networking, and resilient infrastructure in an in-home lab before documenting what works.

Operating principle

Every experiment should produce a configuration, measurement, lesson, or open reference that another household can use.

01 / Active direction

From experiment to evidence.

R&D connects the physical testbed to the guides and benchmark matrix published across the site.

01 / LOCAL AI

Ollama at the edge

Evaluate local models for voice, vision, coding, automation, and private document context on practical home hardware.

02 / VOICE

End-to-end voice testing

Trace microphone capture, wake word, STT, Home Assistant intent, Piper TTS, network transport, and playback.

03 / INFRASTRUCTURE

Private system design

Build repeatable Proxmox VM/LXC patterns with isolated backend networks, secure access, and dependable recovery paths.

Unbound recursive DNS

Pair privacy-focused recursive resolution with Pi-hole or AdGuard Home for local filtering without routine dependence on public DNS providers.

05 / FILES

Samba file sharing

Test fast, browsable cross-platform file access for media libraries, pictures, backups, and the applications that use them.

06 / MEDIA

Home media services

07 / AUDIO

08 / CLOUD

09 / PHOTOS

10 / DOCUMENTS

02 / Design implementation requirements

A testbed with standards.

These requirements keep the work affordable, honest, and useful to both households and potential technology partners.

Private by default

Prefer local processing, document network boundaries, and verify idle behavior rather than assuming privacy from product claims.

Repeatable builds

Record hardware, versions, configuration, resource allocation, and test conditions so results can be reproduced.

Measured performance

Track latency, accuracy, throughput, memory, CPU/GPU use, power, and failure behavior across the full workflow.

Accessible cost

Favor inexpensive, repairable, well-documented components and explain the tradeoffs behind each recommendation.

Open documentation

Publish implementation guides, test notes, references, and limitations so the community can inspect and improve the work.

Responsible partnerships

Accept sponsored hardware or software for evaluation while keeping test conditions and results transparent.
