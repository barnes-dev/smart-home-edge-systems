How to use this guide

Perform the steps in order. Do not create all containers first and tune them later. Each CT has a create, configure, tune, validate, and checkpoint phase. Stop at a failed checkpoint and repair it before continuing.

Commands marked DESTRUCTIVE can erase disks or delete containers. Replace values in angle brackets. Run Proxmox host commands on the host, LXC commands inside the named CT, and Docker commands inside VM 113.

Build variables and inventory

Create an installation worksheet before powering on the host:

Variable Target value
Proxmox hostname infotainment
Proxmox management IP 192.168.86.235/24
Gateway <LAN-GATEWAY>
DNS <DNS-1>, <DNS-2>
Primary bridge vmbr0
Backend bridge vmbr1
Storage disk IDs <record by-id paths>
NVMe storage ID <record by-id path>
Backup share /mnt/storage/homelab-backups
Proxmox version 9.2.3 target, verify current release before install

Record disk model and serial values with:

lsblk -o NAME,SIZE,MODEL,SERIAL,FSTYPE,MOUNTPOINTS
ls -l /dev/disk/by-id/

Step 1: Create the Proxmox installation USB

  1. Download the Proxmox VE ISO from the official Proxmox download page.

  2. Download the SHA-256 checksum from the same release page.

  3. On Windows, open PowerShell and calculate the ISO checksum:

    Get-FileHash .\proxmox-ve_*.iso -Algorithm SHA256

  4. Compare the result with the published checksum character-for-character.

  5. Insert an 8 GB or larger USB drive and close every Explorer window using it.

  6. In Rufus, select the ISO and the verified USB drive.

  7. Select DD Image mode if Rufus asks which write mode to use.

  8. Write the image, safely eject it, and label it PROXMOX-INSTALL.

The Proxmox installer USB is a hybrid ISO. Do not manually partition it first. Writing the ISO replaces the partition table and creates the boot layout required by the release.

For a separate provisioning USB, use GPT with a 512 MiB FAT32 EFI partition, an 8 GiB or larger exFAT provisioning partition, and a remaining exFAT data partition. Do not store the only credential or backup copy on removable media.

Step 2: Boot and install Proxmox VE

  1. Connect the installer USB and wired Ethernet.
  2. Power on the host and open the UEFI one-time boot menu.
  3. Select the USB entry marked UEFI.
  4. Choose Install Proxmox VE.
  5. Select the system NVMe only. Confirm its model and serial. Do not select the bulk storage disk.
  6. Select the target filesystem. For this single-node design, use the filesystem chosen in the storage worksheet; do not enable ZFS without a deliberate disk layout and memory budget.
  7. Set timezone, keyboard, root password, and administrative email.
  8. Set hostname infotainment and management IP 192.168.86.235/24, using the real gateway and DNS values.
  9. Review the final summary and begin installation.
  10. Remove the USB when the installer reboots.
  11. Browse to https://192.168.86.235:8006 and sign in as root.

Checkpoint: confirm the web interface loads, the hostname resolves, and the physical network link is stable before continuing.

Step 3: Update and baseline the Proxmox host

Run on the host:

pveversion -v
hostnamectl
ip -br addr
systemctl --failed
apt update
apt full-upgrade
reboot

After reboot:

pvesm status
pvesh get /nodes/$(hostname)/storage
lsblk -o NAME,SIZE,MODEL,SERIAL,FSTYPE,MOUNTPOINTS

Enable IOMMU only when GPU or device passthrough is required. Confirm the firmware setting first, then follow the Proxmox release documentation for the correct kernel parameter. Do not enable passthrough on a device still needed by the host.

Step 4: Partition and mount the storage array

The system NVMe is for Proxmox, CT operating systems, databases, metadata, and caches. The storage array is for media, photos, documents, downloads, backups, and other bulk data.

Single ext4 data disk

DESTRUCTIVE: replace the device path only after verifying model and serial three times.

lsblk -o NAME,SIZE,MODEL,SERIAL
wipefs -n /dev/disk/by-id/<DATA-DISK-ID>
parted /dev/disk/by-id/<DATA-DISK-ID> --script mklabel gpt
parted /dev/disk/by-id/<DATA-DISK-ID> --script mkpart primary ext4 1MiB 100%
mkfs.ext4 -L bulkdata /dev/disk/by-id/<DATA-DISK-ID>-part1
mkdir -p /mnt/storage
blkid /dev/disk/by-id/<DATA-DISK-ID>-part1

Add the UUID to /etc/fstab:

UUID=<DATA-UUID> /mnt/storage ext4 defaults,noatime 0 2

Then mount and create the architecture directories:

mount -a
findmnt /mnt/storage
mkdir -p /mnt/storage/{media,audiobooks,documents,photos,downloads,3d_assets,game_backups,homelab-backups/configs}
mkdir -p /mnt/storage/homelab-backups/configs/{compute-node,infotainment-node}

For multiple disks, stop and choose ZFS, hardware RAID, or another design before formatting anything. Backups are required regardless of the redundancy choice.

Step 5: Create the host bridges

Configure vmbr0 for the primary LAN and vmbr1 for the isolated database/backend segment. Use the Proxmox GUI or the host network configuration, then verify before creating CTs:

ip -br link
ip -br addr
bridge link
ping -c 3 <LAN-GATEWAY>

The target addresses are:

Bridge Purpose Example
vmbr0 Primary LAN CT 100, 102-110, VM 113
vmbr1 Backend isolation CT 101 at 10.0.20.10

Step 6: Install CT 100 - Samba-NAS

Create CT 100

Use the official Community Scripts catalog, inspect the current script, and select an unprivileged Debian LXC. Use CTID 100, hostname samba-nas, 2 vCPUs, 1 GiB RAM, 16 GiB NVMe root disk, and a fixed address of 192.168.86.234/24 on vmbr0.

Example command shape; use the exact current catalog URL and script name after review:

bash -c "$(curl -fsSL https://raw.githubusercontent.com/community-scripts/ProxmoxVE/main/ct/samba.sh)"

Configure CT 100

On the host, stop the CT and add the storage bind mount:

pct stop 100
pct set 100 --cores 2 --memory 1024 --swap 512 --onboot 1
pct set 100 --startup order=10,up=30,down=30
pct set 100 --mp0 /mnt/storage,mp=/mnt/storage
pct start 100

Inside CT 100:

apt update && apt full-upgrade
apt install -y samba acl
smbpasswd -a <SMB-USER>

Create shares for media, audiobooks, documents, photos, downloads, 3d_assets, and homelab-backups. Do not expose the Nextcloud data directory as a general-purpose share. Apply least-privilege users and groups.

Validate CT 100

pct exec 100 -- test -d /mnt/storage/media
pct exec 100 -- systemctl is-active smbd
smbclient -L //192.168.86.234 -U <SMB-USER>

Checkpoint: copy a disposable test file through SMB and confirm it is readable from the host and from the intended application CT.

Step 7: Install CT 101 - PostgreSQL

Create CT 101

Use a current Debian LXC or the reviewed PostgreSQL Community Script. Set CTID 101, hostname postgres-db, 4 vCPUs, 4 GiB RAM, 32 GiB NVMe root disk, and 10.0.20.10/24 on vmbr1. Restrict the firewall to application clients.

bash -c "$(curl -fsSL https://raw.githubusercontent.com/community-scripts/ProxmoxVE/main/ct/postgresql.sh)"

Configure CT 101

The active PostgreSQL directory is on the fast database storage, not the bulk USB share. If a dedicated host mount is used, stop the CT and add it only after formatting and mounting the host storage:

pct stop 101
pct set 101 --cores 4 --memory 4096 --swap 1024 --onboot 1
pct set 101 --startup order=20,up=45,down=45
pct set 101 --mp0 /mnt/pve/db_data,mp=/var/lib/postgresql/data
pct start 101

Inside CT 101, create one database and one least-privilege role per application. Never use the PostgreSQL superuser in application connection strings:

sudo -u postgres psql
CREATE ROLE <APP_USER> LOGIN PASSWORD '<LONG-RANDOM-PASSWORD>';
CREATE DATABASE <APP_DB> OWNER <APP_USER>;
\q

Configure pg_hba.conf for only the required backend and application addresses. Configure nightly pg_dump files into /mnt/storage/homelab-backups/configs/infotainment-node/postgres-dumps through a controlled mount or backup job.

Validate CT 101

pct exec 101 -- systemctl is-active postgresql
pct exec 101 -- sudo -u postgres psql -c 'select version();'
pg_dump --format=custom --file=/tmp/postgres-check.dump <APP_DB>

Troubleshooting

A container cannot write to a bind mount. Check host ownership, ACLs, unprivileged UID/GID mappings, and the read-only flag. Do not make every CT privileged to hide a permissions problem.

A media server cannot transcode. Check /dev/dri, device permissions, driver support, and the application log. Confirm CPU transcoding works before debugging Quick Sync.

PostgreSQL is slow. Keep active data and WAL on NVMe, inspect iostat, check memory pressure, and confirm that USB bulk storage is not being used for the database.

Docker services restart repeatedly. Run docker compose logs --tail=100, inspect the generated .env, verify mounted paths, and verify database and Redis connectivity. Do not enable restart loops while the root error is unknown.

A Community Script fails. Save the output, review the current script source and prerequisites, and repair or remove the partial CT deliberately. Do not rerun a destructive script repeatedly against the same broken container.
